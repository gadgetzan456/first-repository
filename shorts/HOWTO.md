# ショート動画 台本づくり How to（題材を問わない共通版）

制作者の知識を正確に引き出しながら、ショート動画の台本・ナレーション・素材リストを作るための手順。
題材ごとの実例は各フォルダの `howto.md` に置く（例：`shiren6-tessoku/howto.md`）。

## 基本方針

- 内容（事実・主張・ノウハウ）は制作者のもの。AIは構成・整形・不足の指摘・音声向けの調整を担当する
- 確認できない事実は推測で埋めない。制作者から受け取るか、「要確認」と明記して残す
- 一度に完成を目指さず、小さく出して直してもらう

## 手順

### 1. 依頼内容の確認
- 題材、伝えたいこと、想定する視聴者を一文で言い直して確認する
- 比喩や造語が出てきたら、「実物か比喩か」を最初に確認する（取り違えると全体をやり直すことになる）
- 形式の制約（縦型/横型、長さ）が本当に必要かを聞く。プラットフォームの上限と制作者の希望は別
- 音声の方式（合成音声の話者、本人の声、字幕のみ）と口調を決める

### 2. 事実の確認
- 固有名詞や数値は、まずWeb検索などで確認できるか試す
- 確認できない場合は、推測で項目を作らず、制作者から受け取る。検索で見つからなかったことも伝える
- 表記があやしい固有名詞は、台本に入れたうえで「要確認」と記録する

### 3. 型（構成テンプレート）を決める
- 型は題材に合わせて作る。典型例：
  - 一覧型：オープニング → 項目を順に紹介 → まとめ/CTA
  - 問題解決型：悩み → 原因 → 対処 → まとめ
  - 手順型：結論 → 手順1〜n → 注意点
  - 比較型：対象A/B → 観点ごとの違い → おすすめ
- 項目ごとの繰り返し単位（例：タイトル → 理由 → 対処）を決める
- 型は途中で変えてよい。変えたら全体を通して見直す

### 4. 内容を少しずつ受け取る
- 項目ごとに受け取る。途中で切れた入力は補完せず、続きを聞く
- 制作者の言い回しはできるだけ残し、意味を変えずに口調だけ整える
- 破棄を求められたら、以降使わない。保存していなければ、その旨も伝える

### 5. 不足分は「仮」で置く
- 未提供の部分は案を書き、**仮（🟡）と明示**する
- 仮の部分だけを抜き出した表を作り、制作者に差し替えてもらう
- 確定した部分は確定（✅）と書き分ける

### 6. 音声合成向けに整える
- 話者を決め、語尾・口調を合わせる
- 数字・記号・難読語・造語は、ひらがなやカタカナに置換する
- 読みの最終確認は、制作者が実際に聞いて行う
- 画像やカットを切り替える箇所は、1行ずつ別の音声にできるよう区切る
- 間が詰まるときは読点を足す。テンポ調整は編集側で行う

### 7. 素材リストを作る
- 背景動画：パートごとに内容と長さの目安（リピート前提なら数秒〜十数秒）
- 画像：用途と表示タイミング（言い始める瞬間に出す、など）
- テロップ、背景、ロゴなどの任意素材も書く

### 8. 通して確認し、保存する
- 部分ごとの修正のあとに、必ず全文を通して見せる
- 確認が残っている点を台本の末尾に書く
- 保存先は `shorts/<動画名>/`。構成：
  - `script.md`：通し台本、素材リスト、確認事項
  - `narration.txt`：音声合成に貼る用（1行1音声）
  - `howto.md`：その動画で使った手順と学び（実例）

## 次工程（動画の組み立て）

1. 音声合成でナレーションを書き出す
2. 音声の長さを測り、パートごとの時間を決める
3. 背景動画・画像・テロップを配置する
4. 必要なら字幕（SRT）を音声の長さから作る
5. 要確認の点を解消して書き出す

## 依頼テンプレート

```
題材：
伝えたいこと（比喩なら比喩と明記）：
視聴者：
音声：（話者／本人の声／字幕のみ） 口調：
長さ・形式：（制約があれば）
構成の型：（なければ相談したい）
項目：
 1. 
 2. 
素材：使える動画・画像の有無
```

## チェックリスト

- [ ] 比喩・造語の意味を確認した
- [ ] 事実はすべて、確認済みか「要確認」にしてある
- [ ] 仮（🟡）の部分が表で一覧できる
- [ ] 音声向けの読みを置換した
- [ ] 素材リストに、動画・画像・表示タイミングがある
- [ ] 通しで読み返した
