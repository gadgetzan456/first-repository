# ショート動画 台本づくり How to（題材を問わない共通版）

制作者の知識を正確に引き出しながら、ショート動画の台本・ナレーション・素材リストを作るための手順。
題材ごとの実例は各フォルダの `howto.md` に置く（例：`shiren6-tessoku/howto.md`）。

## 基本方針

- 内容（事実・主張・ノウハウ）は制作者のもの。AIは構成・整形・不足の指摘・音声向けの調整を担当する
- 確認できない事実は推測で埋めない。制作者から受け取るか、「要確認」と明記して残す
- 一度に完成を目指さず、小さく出して直してもらう

## 手順

### 1. 依頼内容の確認
- 題材、伝えたいこと、想定する視聴者を一文で言い直して確認する
- 比喩や造語が出てきたら、「実物か比喩か」を最初に確認する（取り違えると全体をやり直すことになる）
- 形式の制約（縦型/横型、長さ）が本当に必要かを聞く。プラットフォームの上限と制作者の希望は別
- 音声の方式（合成音声の話者、本人の声、字幕のみ）と口調を決める

### 2. 事実の確認
- 固有名詞や数値は、まずWeb検索などで確認できるか試す
- 確認できない場合は、推測で項目を作らず、制作者から受け取る。検索で見つからなかったことも伝える
- 表記があやしい固有名詞は、台本に入れたうえで「要確認」と記録する

### 3. 型（構成テンプレート）を決める
- 型は題材に合わせて作る。典型例：
  - 一覧型：オープニング → 項目を順に紹介 → まとめ/CTA
  - 問題解決型：悩み → 原因 → 対処 → まとめ
  - 手順型：結論 → 手順1〜n → 注意点
  - 比較型：対象A/B → 観点ごとの違い → おすすめ
- 項目ごとの繰り返し単位（例：タイトル → 理由 → 対処）を決める
- 型は途中で変えてよい。変えたら全体を通して見直す

### 4. 内容を少しずつ受け取る
- 一度に全部をもらおうとせず、状況ごとに受け取る
- 途切れた入力は補完せず、「続きを送ってください」と返す
- 破棄を求められたら、保存していないことを伝えて以降は使わない
- 受け取った文は、意味を変えずに口調だけ整える

### 5. 足りない部分は「仮」で置く
- 理由や対処が未提供のときは、自分の案を書いて**「仮（🟡）」を明示**する
- 仮の内容は表にまとめて見せ、制作者に直してもらう
- 確定した部分は「確定（✅）」と書き分ける。何が確定済みかが一目で分かる
- 仮の内容は、制作者の修正文を受け取ったら、語尾だけ整えてそのまま反映する

### 6. VOICEVOX向けに整える
- 話者に合わせて語尾を決める（例：ずんだもん「〜のだ」）。話者は最初に確認する
- 口調は制作者の希望に合わせる
- 読み間違えやすい部分を置換する
  - 数字や記号：「87%」→「はちじゅうななパーセント」、「？」→「はてなマーク」
  - 難読語や造語：ひらがなに置換
- 読みの最終確認は制作者がVOICEVOXで聞いて行う。違和感があればひらがなに直す
- 間が詰まる場合は読点を増やす。切り替えのテンポは、1文ずつ別音声ファイルにして編集で合わせる
- 画像を切り替える箇所（敵の名前など）は、名前ごとに読点で区切り、1行ずつの音声にする（narration.txt）

### 7. 素材リストを作る
台本が固まったら、制作者が用意するものを一覧にする。
- **背景動画**：パートごとに内容と長さの目安（リピート前提なので数秒〜十数秒）
- **画像**：登場する敵やアイテムなど。表示タイミング（名前を言い始める瞬間）も記載
- **背景画像・ロゴ**：任意

### 7-2. 確認用の画像を集める
- 画像リストの名前を攻略サイトで探し、画像URLと出典ページを `shorts/<動画名>/images.tsv` に書く
- `python3 shorts/tools/fetch_images.py shorts/<動画名>/images.tsv` で `ref_images/` に取得し、番号つきの一覧画像 `_sheet.png` を制作者に見せる
- 画像はコミットしない（`ref_images/` は .gitignore 済み）。別の環境では、同じコマンドで取り直せる
- 手順・出典・気づいたことは `images.md` に書く（実例：`shiren6-dorobou/images.md`）

### 8. 通しで確認し、ファイルにまとめる
- 会話では部分ごとに直していくが、最後に全文を通して見せる
- 確認が残っている点を台本の末尾に書いておく
- 保存先は `shorts/<動画名>/`。構成：
  - `script.md`：通し台本、素材リスト、確認事項
  - `narration.txt`：VOICEVOXに貼る用（1行1音声）
  - `howto.md`：このメソッド

## 次工程（ローカルで動画を作る）

1. `narration.txt` を1行ずつVOICEVOXに入力し、音声ファイルを書き出す
2. 各音声の長さを測り、`script.md` のパートごとに時間を割り当てる
3. 背景動画と画像を用意し、各パートでリピート再生するように配置する
4. タイトルとテロップを入れる
5. 必要なら字幕（SRT）を、音声の長さから作る
6. 確認が残っている点を解消してから書き出す

## 再利用用の依頼テンプレート

```
題材：
伝えたいこと（比喩なら比喩と明記）：
音声：VOICEVOX（話者：   ）／口調：
長さ：（制約があれば）
状況・項目：
 1. タイトル／理由／対処
 2. ...
素材：使える動画・画像の有無
```

## 学び（失敗と対処）

- 比喩を実物と取り違えた → 「実在する本ではなく心の中のもの」と説明を受けて修正
- 勝手に作った台本は破棄を求められた → 内容は制作者が決める。AIは構成・整形・不足の指摘に徹する
- 公式情報が見つからなかった → 推測で埋めず、制作者の知識を一次情報にした
- モンスター名などの固有名詞は、制作者の表記を一次資料にする。何度も要確認にしない（お香の使い方の回）
- 対処の一文に、前提となる仕組みが省かれていることがある（例：「トドの壺も期待して押すなら」）→ 視聴者が知らない前提（トドの壺は泥棒用で、未鑑定の壺をそれと期待して押す）を聞き出し、状況の行として台本に足す（泥棒の回）
- 負け数などの一言（「（1敗）」）は、別テロップにせず、該当する台本の行末に付ける（泥棒の回）
- 画像を探すと事実の食い違いが見つかることがある（「風遁忍者」が一覧になく、丸太で飛ばすのは木遁忍者）→ 台本は直さず、要確認として制作者に聞く（泥棒の回）
